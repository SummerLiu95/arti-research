# M4 后端服务

日期：2026-09-29
状态：Completed

## 背景

完成 TASKS M4：FastAPI REST API + Typer CLI，共用 service 层，覆盖筛选/分页/校验/错误响应。

## 完成内容

- `api/schemas.py`：响应模型（EntityOut / RelationshipOut / RelationshipDetailOut / 分页包装 / GraphOut）
- `api/service.py`：查询 service 层（API 与 CLI 共用）——类型/状态/公司双向模糊/评分区间/时点有效性筛选 + 分页 + 评分降序
- `api/main.py`：端点 `/health`、`/entities`、`/relationships`（筛选+分页）、`/relationships/{id}`（证据链+评分构成）、`/graph`（Cytoscape 节点/边格式，支持 center 过滤）；CORS 只放 GET
- `cli/main.py`：`relationships` / `detail` / `graph` 三个命令，JSON 输出，与 API 等价
- `tests/test_api.py`：13 个用例（SQLite 内存库 + dependency override），关键路径 + 失败边界（404、min>max 422、非法类型/页码 422、未知 graph center 404）
- 模型改动：JSONB → `JSON().with_variant(JSONB, "postgresql")`，使测试可用 SQLite 而生产仍用 JSONB

## 验证

- pytest 累计 25 passed（管道 6 + 评分 6 + API 13）
- CLI 对真实库实测：`relationships --type supplier --min-score 60` 返回 4 条供应商关系，JSON 结构正确
- 未验证：uvicorn 起服务后的人工访问（TestClient 已覆盖同一代码路径，T6.3 compose 整体验证时补）

## 经验（已同步 RULESBOOK.md）

- ORM 查询想做双向公司匹配时不能用 union 拼接 Query，应双别名 join + or_
- FastAPI 测试用 SQLite 时，JSONB 列要写成 with_variant 形式，否则建表失败
