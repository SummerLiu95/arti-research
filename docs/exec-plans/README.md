# Execution Plans Archive

本目录用于归档功能实现完成后的记录性文档。它保存"这次实际怎么做完了"，不是未来计划清单，也不是 PRD 或架构正文。

## 什么时候写

- 一个功能、里程碑、修复或技术 spike 已经完成（例如：采集管道、关系抽取、评分引擎、API、前端某个视图）。
- 这次实现包含值得后来者理解的取舍、验证结果、遗留风险或后续动作。
- 相关信息如果只留在聊天记录中，下一位 agent 很难恢复上下文。

## 命名建议

使用日期和简短主题：

```text
YYYY-MM-DD-brief-topic.md
```

示例：

```text
2026-09-29-data-pipeline.md
2026-09-30-scoring-engine.md
```

## 文档模板

```md
# 标题

日期：
状态：Completed / Partially Completed / Superseded

## 背景

这次实现或审核要解决什么问题。

## 完成内容

- 关键改动 1
- 关键改动 2

## 验证

- 运行过的检查、测试或人工审核。
- 未能验证的内容要明确写出。

## 经验与后续

- 值得补充到 `docs/RULESBOOK.md` 的经验。
- 仍需后续处理的风险或任务。
```

## 维护边界

- 不把未完成的实施计划放在这里；未完成计划应留在 `docs/TASKS.md` 或当前任务上下文中。
- 不复制 PRD、ARCHITECTURE 的正文内容，只记录实现过程中的决策与结果。
- 如果一次归档产生了可复用教训，也同步补充 `docs/RULESBOOK.md`。
