# PRD — ARTi 供应链与合作关系研究服务

日期：2026-09-29
状态：Draft

## 1. 背景与目标

ARTi 研发岗位挑战：基于合法可访问的公开资料，构建一个**可复现的供应链与合作关系研究服务**。研究对象已确定为 **NVIDIA**（题目允许 NVIDIA 或宇树科技二选一）。

核心目标不是生成一段摘要，而是把**关系结论、证据、时效、方向和可解释评分连接起来**，让 reviewer 可以理解、运行和追溯判断。

## 2. 研究范围

### 2.1 研究对象

- **NVIDIA（英伟达，NASDAQ: NVDA）**——已确定
- README 需明确：公司实体（NVIDIA Corporation）、证券标识（NASDAQ: NVDA）、研究时间截点、覆盖范围与不覆盖边界
- 区分已确认事实、合理推断和未知信息，声明不构成投资建议
- 覆盖范围初定：GPU/数据中心供应链（台积电、SK 海力士等）、主要客户（ hyperscaler 云厂商）、合作伙伴、投资/被投对象、可比公司（AMD、Intel 等）

### 2.2 关系类型（至少覆盖）

| 类型 | 说明 |
|---|---|
| supplier | 供应商 |
| customer | 客户 |
| partner | 合作伙伴 |
| investor_or_investee | 投资/被投对象 |
| peer | 可比公司 |

每条关系需明确：方向、实体身份、事实/推断/未知状态、时效性。

### 2.3 证据要求

每项关系保留：

- source URL、publisher
- 发布时间或获取时间
- evidence locator（证据定位，可回溯到原文位置）
- 访问/许可限制说明

需处理：实体歧义、来源冲突、过期信息和新闻共振误判。

### 2.4 数据合规约束

- 仅使用合法可访问的公开资料
- 不得绕过 robots、登录、付费墙、验证码、限流或其他访问控制
- 不得提交密钥、个人数据、客户机密、受限原始数据或未授权内容

## 3. 功能需求

### F1 数据采集管道

- 从公开数据源（财报、公告、新闻、供应链披露等）采集
- 采集结果存 fixture/snapshot，复现不依赖实时抓取
- 公开说明数据源、采集、清洗与处理方案

### F2 关系建模

- 结构化存储 F1 抽取的关系（5 类，带方向、状态、时效）
- 实体消歧（如别名、同名公司）

### F3 评分引擎

- 为关联上市公司计算 0–100 相关度或置信度
- 评分公式透明可复算，说明证据可信度、独立性、时效、关系类型和可量化信息如何影响评分

### F4 REST API

- HTTP JSON API：公司关系查询
- 支持筛选（关系类型、相关度、时间等）、分页
- 输入校验与明确错误响应

### F5 CLI

- 与 API 等价的脚本化入口

### F6 前端展示（自选增强，岗位偏全栈）

- 关系图视图（Cytoscape.js 网络图）+ 关系列表 + 证据/评分构成展开
- 降低 reviewer 理解与追溯成本

## 4. 交付产物

1. **公开 GitHub 仓库**，含 README、数据源说明、启动/测试命令、复现步骤
2. **研究数据集**（结构化关系 + 证据链 + 评分，含明确数据截点）
3. **采集与处理管道**（可重跑）
4. **REST API + CLI**
5. **前端应用**（React + Vite，展示增强项）

## 6. 优先级原则

可复现性 > 证据可追溯性 > 评分可解释性 > 数据覆盖量。

宁可少量关系条条有证据可回溯，也不要大量没出处的数据。失败用例与边界处理（来源冲突、过期信息、实体歧义）是加分项。
